01 · Frontend

Không phải file .jsx nào cũng chỉ có component

Nhấn vào từng loại để xem tiêu chí, vai trò và vị trí thật trong source. Cách phân biệt là nhìn vào trách nhiệm và giá trị trả về, không chỉ nhìn tên file.

Reusable UI

Props + callback

SimulationNavigation nhận vị trí và onPrevious/onNext; nó không biết simulation cụ thể. Vì vậy có thể dùng lại cho mọi workflow nhiều bước.

State ownership

Page / hook giữ state

SimulationAttemptPage dùng useSimulationAttempt để giữ answer, validation, current task và submit status; component con chỉ hiển thị và phát sự kiện.

Mở rộng

Tách theo trách nhiệm

Thêm prop hoặc component artifact mới thay vì để card tự fetch. Khi logic dùng lại tăng, đưa vào hook; khi nhiều vùng cần cùng state mới cân nhắc Context.

React giúp gì? JSX/composition ghép UI nhỏ thành page; props truyền dữ liệu một chiều; useState làm UI phản ứng với state; useEffect chạy side effect như tải API sau render; React Router đổi route không reload cả app; reconciliation cập nhật phần DOM cần đổi.

03 · End-to-end trace

Đi theo một yêu cầu thật từ UI đến dữ liệu và quay về UI

Chọn kịch bản, rồi dùng bước trước/sau. Node đang sáng là nơi request đang được xử lý; phần chi tiết cho biết việc gì xảy ra và file nào chịu trách nhiệm.

Điểm mấu chốt: frontend không truy vấn PostgreSQL. Controller không viết business rule. LLM không truy vấn PostgreSQL. Mỗi lớp chỉ làm đúng phần việc của mình.

04 · AI agent

Syn là bounded, orchestrated, single-agent workflow

Syn không phải chatbot tự do hay agent chạy nền. Nó có một vòng xử lý được backend điều phối: đọc memory → policy chọn tool plan → tool server chạy → tùy điều kiện gọi tối đa một model → kiểm tra output → cập nhật memory → trả response.

Có memory

Bounded session memory

syn_sessions lưu language, stage, goal, covered topics, next action, last intent/path trong summary có version. Owner-scoped, 30 ngày, xóa được; không lưu raw chat.

Không phải RAG

Controlled retrieval

Không có embedding, vector DB hay semantic retrieval. Toolbox dùng JDBC đọc evidence sở hữu, path ACTIVE, resource REVIEWED và simulation PUBLISHED — đây là retrieval có allowlist, không phải vector RAG.

Không tự quyết

Artifacts do server làm chủ

Result card, comparison card, resource card và plan draft được toolbox tạo từ dữ liệu đã lọc. Model chỉ diễn đạt text và suggestions hợp schema.

05 · Control, evidence & fallback

Syn không tin ngay vào user input, model output, hoặc dữ liệu bên ngoài

Luồng an toàn có nhiều lớp. Đây là lý do agent có thể hữu ích mà vẫn không biến thành hệ thống tự đưa ra quyết định nghề nghiệp.

01

Gateway và request contract

Nginx giới hạn Syn 10 request/phút theo client với burst nhỏ, body tối đa 16 KiB. DTO giới hạn message 600 ký tự và chỉ chấp nhận action/language trong enum.

02

Authorization + ownership

Spring Security yêu cầu authenticated guidance request; service kiểm tra account tồn tại, role STUDENT, status ACTIVE và attempt/session thuộc đúng sinh viên.

03

Deterministic policy trước model

Prompt injection, yêu cầu system prompt/API key/answer key, guarantee hoặc “chọn nghề thay tôi” bị chặn bằng safety boundary trước provider. Model không chọn SQL, URL hay tool.

04

Evidence và artifact có provenance

Toolbox chỉ đọc nguồn server-owned đã lọc. Response hiển thị activity và evidence references; score/evaluation vẫn là deterministic data, không do Syn thay đổi.

05

Schema + fallback

Gemini phải trả JSON { text, suggestions }; backend kiểm tra parse, length và finish state. Timeout, provider rejection hay output lỗi trả Standard guidance với artifacts đã tạo, không trả raw provider error.

06 · Model selection

Tên model cần chính xác trước khi nâng cấp

Cấu hình hiện tại dùng gemini-3.5-flash-lite. Tài liệu Gemini chính thức hiện không liệt kê model ID gemini-3.6-flash-lite; lựa chọn 3.6 đúng tên là gemini-3.6-flash.

Hiện tại

Gemini 3.5 Flash-Lite

Hợp lý khi ưu tiên chi phí thấp, latency thấp và lưu lượng cao cho synthesis đơn giản. Đây là nhánh Lite hiện có thật trong cấu hình dự án.

Đề xuất nâng cấp

Gemini 3.6 Flash

Hợp lý khi muốn chất lượng diễn giải, tiếng Việt, structured output và khả năng xử lý agent context tốt hơn mà vẫn cần tốc độ/chi phí cân bằng. Syn đã tự làm routing/retrieval/control bằng code, nên không cần model Pro cho autonomous planning dài.

Đổi model không bỏ qua kiểm thử: chạy lại schema, timeout, Vietnamese, injection, fallback và gateway smoke test.

Nguồn: Gemini 3.6 Flash, model overview, release notes.

07 · Future scope, not current MVP

Nếu thêm search engine, search phải là tool bị kiểm soát

Hiện tại Syn không browse web; US-03 loại trừ unrestricted web browsing. Nếu được duyệt scope, search engine không được trao trực tiếp cho model. Nó phải là server-side tool có policy, source verification và fallback.

1 · Gate

Policy chấp thuận

Chỉ intent được duyệt như learning resources mới có thể yêu cầu search. Query do server xây từ skill/path đã resolve, không tin raw user instruction.

2 · SearchAdapter

Tra cứu có giới hạn

Server gọi search API với quota, allowlisted domain, safe-search và giới hạn thời gian. Model không có key, không tự gọi URL.

3 · Verify

Lọc và đối chiếu

Kiểm tra HTTPS, publisher, license/provenance, duplicate, độ liên quan skill trước path; bỏ trang chứa nội dung không phù hợp hoặc instruction độc hại.

4 · Grounded reasoning

Chỉ tóm tắt evidence đã lọc

Model nhận top sources đã được kiểm tra cùng evidence của sinh viên. Nó nêu giới hạn, so sánh và đề xuất thử nghiệm; không suy ra career fit.

5 · Human review

Resource bền vững phải reviewed

Nguồn muốn xuất hiện lâu dài đi vào trạng thái pending review; chỉ record REVIEWED mới thành catalog/resource chuẩn của Syn.

6 · Fallback

Không có nguồn vẫn trung thực

Search fail hoặc không đủ evidence thì quay về resource REVIEWED trong Postgres hoặc nói rõ chưa tìm thấy nguồn đã kiểm tra — không bịa link.

Ý nghĩa: agent không chỉ “tra cứu tài liệu”. Backend buộc nó xác minh nguồn, liên kết source với skill/path/evidence, tạo artifact có cấu trúc, lưu provenance và chỉ sau đó mới cho model diễn đạt.

CareerSim là hệ thống khám phá nghề nghiệp có bằng chứng. Syn hỗ trợ diễn giải và đề xuất bước thử; quyết định cuối cùng, điểm khách quan và dữ liệu nguồn vẫn nằm trong các boundary do hệ thống kiểm soát.
